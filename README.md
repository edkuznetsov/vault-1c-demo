# Vault + PostgreSQL + 1С

Минимальный учебный стенд к докладу «Храним свои секретики». В репозитории есть
[проект EDT](1c/ПолучениеСекретовВолт) с исходниками и готовой
[обработкой в `bin`](1c/ПолучениеСекретовВолт/bin/ПолучениеСекретаВолт.epf),
а также всё необходимое для запуска трёх контейнеров: `postgres`, `vault`,
`proxy`. Обработка читает один секрет KV v2 двумя способами: через JWT login в
Vault и через выделенный Vault Proxy с AppRole Auto-Auth.

## Запуск

Нужен Docker Engine с Compose v2. На Windows запустите Docker Desktop; на
Linux убедитесь, что у текущего пользователя есть доступ к Docker Engine.

### Windows (PowerShell)

Откройте PowerShell в корне репозитория:

```powershell
.\scripts\start-demo.ps1
```

Если PowerShell блокирует запуск скрипта:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start-demo.ps1
```

### Linux (sh)

В терминале из корня репозитория:

```sh
sh ./scripts/start-demo.sh
```

Оба скрипта используют `.env` с учебными root token Vault и паролем PostgreSQL,
затем поднимают и настраивают три контейнера. Файл включён в репозиторий: эти
значения публичны и предназначены только для демонстрации. Если `.env` удалён,
скрипт создаст новые случайные учебные значения. Дождитесь сообщения о
готовности контейнеров.

## Проверка

```powershell
docker compose ps
(Invoke-RestMethod http://127.0.0.1:8100/v1/secret/data/onec/database).data.data
```

На Linux тот же запрос:

```sh
docker compose ps
curl -fsS http://127.0.0.1:8100/v1/secret/data/onec/database
```

У контейнеров должен быть статус `healthy`. Второй запрос должен вернуть
`host`, `port`, `database`, `username`, `password` учебной базы. Proxy сам
получает Vault token через AppRole; клиентский token в этом запросе не нужен.

Откройте [обработку из `bin`](1c/ПолучениеСекретовВолт/bin/ПолучениеСекретаВолт.epf)
через «Файл → Открыть» в локальной 1С 8.3.27 и нажмите кнопки «Получить через
токен» и «Получить через прокси». Для редактирования импортируйте папку
`1c/ПолучениеСекретовВолт` как существующий проект EDT;

Vault доступен на `http://127.0.0.1:8200`, Proxy —
на `http://127.0.0.1:8100`, PostgreSQL — на `127.0.0.1:15432`. Запускайте 1С
на том же компьютере, где работает Docker: порты стенда доступны только через
`127.0.0.1`.

Vault UI: <http://127.0.0.1:8200/ui>. Учебный root token скрипт показывает в
терминале; он также находится в локальном `.env`. В Vault CLI секрет называется
`secret/onec/database`, а его HTTP-путь — `secret/data/onec/database`.

## Остановка и повторный запуск

```powershell
docker compose down
```

После обычной остановки снова запустите соответствующий скрипт для Windows
или Linux. Чтобы сбросить учебную базу и начать с новым паролем, выполните
`docker compose down -v`, удалите локальный `.env` и затем запустите скрипт.

## Ограничения

Это публичный учебный стенд: Vault работает в dev mode, TLS отключён, а
`runtime/keys/private.pem` содержит опубликованный учебный закрытый ключ.
Никогда не используйте эти ключи, root token, пароль PostgreSQL и другие
демонстрационные credentials в рабочей среде. Proxy выделен одному приложению
и принудительно подставляет свой Vault token
(`use_auto_auth_token = "force"`); он не подходит как общий шлюз для приложений
с разными правами.
